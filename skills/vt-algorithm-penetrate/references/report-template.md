# 算法穿透报告模板

报告以算法功能分析为主线。以下骨架可按实际算法流调整；ROI 演变、候选抑制、关键判据和数据来源必须覆盖，但不必各自重复展开成大章。

图片引用使用相对路径，Markdown 与 HTML 共用展示图。每张图下写清“它说明该功能的什么行为”，而不是只写样本编号或“检测结果”。

---

## 报告骨架

```markdown
# <算法名> 算法穿透报告

- 报告日期、采集日期及版本：<区分历史采集与本次报告更新>
- 本次方式：<新采集 / 沿用既有 output，未编译、未重跑>
- 输入与参数来源：<简要入口，完整清单移至附录>

用一段话说明算法解决什么问题、主要处理关系与输出边界。默认不评价哪张图漏检或误检。

## 1. 算法流总览

- 算法流解决什么问题，输入输出是什么
- 流程图：输入 → 功能模块 → 判断点 → 输出，明确并行分支和合并关系
- 功能清单表：功能 | 当前源码入口 | 输入 → 输出 | 实际分支 | 采集点
- 阅读约定：图像坐标、统计域、面积单位、显示倍率与图例

## 2. 逐模块穿透分析（每个分析单元一节）

### 2.x <分析单元名>（如：02 阈值分割模块）

- 功能：该模块做什么，为什么放在这个位置，造成什么可观察变化
- 输入／输出：当前源码名称、数据类型与作用，区分强度图、二值区域和显示图
- 关键判断：阈值/分支/参数（名称与当前值），通过与不通过分别发生什么
- 典型场景：把同类缺陷或功能表现放在一起比较，例如 FuncA 下的补齐、保持、删除三种场景；按已有证据选择，不强行凑数
- 紧凑穿透图：每行一种场景，每列一个输入／过程／输出；标明编号、箭头、并行与合并
- 数据表：场景 | 阶段变化（真实值与单位） | 该变化说明什么 | 采集来源
- 全图参照和额外对象明细折叠或链接至附录
- 参数影响仅在帮助理解机制时说明，区分实测与推断

## 3. ROI 穿透链与候选抑制回查

- 正文功能段已包含代表性链，此处提供完整 ROI 索引和采集坐标，逐对象明细默认折叠
- ROI 链只展示该功能相关的阶段，不能为凑流程塞入大量无关空图
- 抑制链按机制归组：来源、何时缩小／消失／被补回、对应判据
- 明确统计对象是矩形内像素、固定追踪集合还是整个连通域，不能混入邻居计数
- 被删除候选不自动命名为真负样本；算法穿透与另行要求的精度验收分开

## 4. 关键判断与功能总结

- 表：功能 | 判断条件原文 | 本次有效值 | 控制候选的哪种变化
- 概括提取、增强、限制、合并、抑制与输出关系
- 区分原采集实测、当前源码静态事实和推断；说明未覆盖的分支

## 附录 A. 数据与运行证据

- 全部采集点数值表、全图参照、完整 ROI 索引、原始文件入口
- 输入、参数、运行环境与数据版本清单
- 既有计时及其范围、异常日志、采集结束时的还原证明
- 更新报告时标明这些是历史记录，不写成此次重新运行或还原的结果

## 附录 B. 源码名称对应（源码变化后更新报告时）

- 当前名称 | 类型与作用 | 旧采集键／旧名称；必要的核心对应可提前到正文
- 当前源码位置、采集版本与当前版本／哈希、静态核对方法与适用范围
- 原文件名不变，正文与图片使用新术语；逻辑变化部分不得套用旧数据结论
- 用户要求另生成一份时，列出上一版入口，使用独立版本文件和展示图
```

## 图表规范

1. **数据流**：总览可用 Mermaid `flowchart TD` 或离线可读的等效图。局部图也要有步骤编号与方向；独立分支用“并行”，并集／交集／差集标明实际运算，不能只靠从左到右的位置暗示关系。
2. **紧凑裁图**：按相关响应的包围范围与必要背景自适应裁剪。取消固定大幅外扩，不让背景或空白画布占据主要版面；小图要实际放大，不能只调用“不放大小图”的缩略接口。
3. **同坐标对照**：同行各阶段使用相同窗口与倍率，跨场景倍率不同时注明；二值掩膜用最近邻，显示裁剪不改变算法的运算域和统计域。
4. **场景组合**：同一功能的不同表现组成一张对照图。图下解释差别如何来自判据；案例数量按证据选择，不按图片文件数量机械分页。
5. **数值与图例**：真实值来自采集文件或对已有掩膜的明确统计，标注单位与统计域。分支合并要区分各自面积、重叠与净新增，不直接相加；叠加色含义一致。
6. **当前名称**：术语、参数名、函数名、图片标题及代码行号与当前源码一致；旧名称仅用于溯源对应。避免把强度图写成区域，或把描述性名称当作物理量。
7. **图文验收**：实际打开代表图和 HTML，确认目标可见、文字无截断、并行／先后无歧义、图数一致、相对链接有效；检查文件编码和 BOM 保持原状。仅更新报告时还应确认原采集证据及用户源码未被改写。
