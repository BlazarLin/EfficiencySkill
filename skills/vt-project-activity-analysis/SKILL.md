# 工程活跃度分析

## 时间规则

- 未指定时间：分析全部 Git 历史。
- 明确时间：使用用户给出的 `近 7 天`、`近 1 个月`、`2026-07-01 至 2026-07-21` 等范围。
- 模糊时间：遇到“近几天”“最近”“这段时间”等表述，先询问具体天数，或起止日期；不要自行猜测。
- 报告开头必须写明实际分析时间范围。

## 支持范围与排除

- 源码：C、C++、Python（`.c/.cc/.cpp/.cxx/.h/.hpp/.py`）。
- 必须排除构建与解释器中间产物，例如 `build*/`、`CMakeFiles/`、`.vs/`、`x64/`、`bin/`、`obj/`、`*.obj`、`*.o`、`*.pdb`、`__pycache__/`、`*.pyc`、`.venv/`、`dist/`、`*.egg-info/`。
- 子工程通过 Git submodule、嵌套 Git 仓库，以及 `CMakeLists.txt`、`pyproject.toml`、`setup.py` 自动发现。
- 子工程与父工程共用同一个 Git 仓库时，只能按路径拆分贡献度；它们没有独立分支历史。独立 Git 子工程和 submodule 则分别执行完整活跃度分析。

## 运行

```bash
# 全历史
bash scripts/full-analysis.sh <仓库路径>

# 明确时间范围
bash scripts/full-analysis.sh <仓库路径> --since "2026-07-01" --until "2026-07-21"
```

仅当用户明确要求圈复杂度、lizard 或 CCN 时运行：

```bash
bash scripts/complexity.sh <仓库路径> --since "2026-07-01"
```

## 输出要求

报告至少包含：

1. 实际时间范围与分析对象。
2. 作者去重、提交数与代码贡献度。
3. 父工程与每个发现的子工程/模块的贡献度。
4. 分支活跃度与最近提交。
5. 被排除的构建/解释器中间产物，以及已被 Git 跟踪的异常产物。
6. 结论必须区分已验证的 Git 数据与工程判断。
