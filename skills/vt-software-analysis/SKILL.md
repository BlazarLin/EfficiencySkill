# 软件分析（竞品/第三方软件）

对没有源码的第三方软件（工业视觉竞品、随包 SDK、交付目录）做技术栈、算法、模型、规则与工程实现的整体分析。核心产出是"哪些是真本事、哪些是包装、哪些能借鉴、哪些会踩坑"，供选型、竞标和自研决策用。

## 红线（强制）

- **不运行**目标 EXE/DLL，不加载其模型推理，不执行解包出的 pickle/TorchScript；不连接厂商服务器。全程静态分析 + 文件解析，原始目录**只读**。
- 解包/解密产物放自己的输出目录，不写回竞品目录；输出不含账号口令与个人联系方式。
- 区分四级证据并在全文标注：**A** 直接证据（指令/PTX/配置原字段/数据库/转储）、**B** 高可信推断（多线索交叉）、**C** 线索（文件名/字符串/公开资料）、**未定**（缺运行或真值）。"未证实"只代表证据不足，不等于不存在。
- 不给未经同图同机同模型 Benchmark 的性能、检出率、误检率结论；不把体积变化解释为速度提升；不把第三方库能力包装成自研算法。

## 组织方式：多轮交叉，不做一次性报告

按三轮递进，多 agent 时拆成三条互补线，单人时按顺序三轮：

1. **广度线**：目录盘点（文件数/EXE/DLL/PDB 计数）、版本资源、导入导出表、配置文件、插件清单——回答"它由什么组成"。
2. **深挖线**：反汇编关键模块、CUDA PTX/SASS、PDB 符号、模型容器解包、日志与数据库考古——回答"它到底怎么实现"。
3. **复核线**：对前两轮的每条关键结论重新取证（用当前文件，不信转述），找增量证据，**明确指出哪些旧结论要修正**——回答"哪些结论站得住"。

汇总时必须出**结论冲突对照表**：逐条列"原结论 / 复核结论 / 采信理由"。这是汇总报告最有价值的部分，不能省。复核结论与原结论冲突时，以基于当前文件重新取证的为准，原结论保留标注供追溯。

## 运行态资产分诊（先挖什么，别一上来就反汇编）

二进制反汇编之前，先把"运行态资产"按价值排好序——这些是厂商自己留下的部署规格与实测数据，取证成本最低、证据等级最高：

| 资产 | 挖什么 | 价值 |
|---|---|---|
| 产品配方目录（product/*.ini、MoBan_WS/*.cfgn、config/cam*/） | 模型路径+输入尺寸+阈值+NMS+类别表+ROI+光源参数 | **部署规格**：回答"现场到底跑什么"，比反汇编快 10 倍 |
| 自文档参数表（ini 里的 help= 行） | 参数名+含义+顺序，厂商自己写的 | 配置 schema 免逆向 |
| 分段耗时日志（工位/模块/OCR 分项计时） | 厂商自证性能：p50/p90/p99、瓶颈定位 | 最硬的性能证据（先做口径抽查） |
| 分钟级生产计数库（SQLite） | 吞吐/开动工位/配方血缘/告警计数 | 产线运行画像 |
| 训练配置明文（ivindex/anomalib yaml/profile.yml） | 训练框架+backbone+超参+阈值 | 模型身份的决定性证据 |
| 拒绝候选落盘日志 | 置信度阈值+被拒分布 | 阈值调优痕迹 |
| 崩溃转储（minidump） | 运行时依赖模块表+版本+CUDA/TRT 路径 | 交付环境实锤 |
| 崩溃风暴日志（同日多次 dump） | 稳定性短板 | 质量评估 |
| IoT/MES API 路由字符串 | 数据外送链路 | 集成形态 |
| 密集/聚类类 UI 槽字符串（lineEdit_DenseID 等） | 上报类别 ID 的配置入口 | 定制逻辑的参数面 |

## 工具箱（按目标选用，Python 一次性脚本即可）

| 目标 | 工具/方法 |
|---|---|
| PE 结构 | pefile：Section、导入/导出表、版本资源、异常目录（**.pdata RUNTIME_FUNCTION 取函数边界，反汇编必须从函数起点开始**）、CodeView 调试信息 |
| 反汇编 | Capstone x64：直接调用、RIP 相对引用、字符串交叉引用、导入桩；**IAT 调用按 DLL 过滤**（Qt5Widgets 构造函数噪声占 80%，只看 opencv/halcon/目标自有 DLL）；先概览调用序列再深入单个函数 |
| Win x64 参数核实 | 寄存器传参 rcx/rdx/r8/r9 + xmm0-3(double) + [rsp+0x20..]；**.rdata 常量回读**（σ=20.0、半径=30px、面积下限 0.01f 这类编译期常量直接取值）；伪代码参数先猜后核，交付前逐条回读 |
| CUDA | cuobjdump：FatBinary 单元数、PTX/SASS、SM 架构、寄存器/Shared 占用；kernel 语义从 PTX 重建伪代码 |
| PDB | DIA2Dump 读公开函数/源码路径/签名；**先做 GUID+Age 与 PE CodeView 匹配校验**，不匹配的旧符号 RVA 不能套用到当前地址 |
| 模型容器 | 先看头部魔数与分段（长度前缀+字段），按"加密破解决策树"处理；已知容器：tar(@PaxHeader)=PyTorch legacy torch.save、ZIP(data/0+code/)=TorchScript、ProgramDesc=Paddle、producer_name=pytorch=ONNX、Darknet cfg 文本 |
| Paddle 程序解析 | **结构化解析不许正则猜**：OpDesc{inputs=1,outputs=2,type=3,attrs=4}、VarDesc{name=1,type=2}、TensorDesc packed dims；**attrs 里的字符串与 op 同池**（batch_norm 有 "momentum" attr），算子计数必须排除 attr 区；变量名正则要处理下划线段（batch_norm_0.tmp_0）；参数 blob=[len][name][ver=0][len][TensorDesc packed dims][data]，形状即架构证据 |
| 成员偏移回溯 | 配置加载函数把值存进 [obj+idx*4+off]（按模型/类别索引的参数数组）→ 全量扫 .text 找同偏移访问点 → 使用点即逻辑所在 |
| 数据文件 | INI/YAML/JSON 直接解析；SQLite 用 sqlite3；minidump 解析模块表、异常地址、逻辑处理器数 |
| 一致性 | SHA-256 判断同名文件是同构建还是仅同大小 |
| 字符串 | ASCII/UTF-16/GBK 三编码导出到 evidence/，grep 关键词定位参数语义、日志格式、API 路由；**Qt UI 构建代码里的控件名（lineEdit_DenseID 类）暴露参数语义**，不要只找算法调用 |

## 加密模型容器破解决策树（按序执行，命中即停）

1. **头部魔数**：明文头直接分流（`ividentify_*`、`zzz<name>zz`、`PK\x03\x04`、`././@PaxHeader`、`*ivicoo*`）——**同扩展名可能多种容器方案，按头分流，别一把钥匙套全部**。
2. **熵+自相关**：等值率峰值位置 = 周期 XOR 的 key 长度候选（注意伪周期，需配明文验证）。
3. **零区直读 key**：找"长零明文区"（结构化 padding/表），plaintext=0 时 **raw 字节即密钥本身**——比频率分析快且准；配合魔数除法常量（如 0x4bda12f684bda13 → ÷432）还原记录结构大小。
4. **差分 XOR**：`plain[i]=cipher[i]^cipher[i-1]^K`（首字节种子不影响 i≥1 的还原）——工业视觉容器高频方案；K 可由零区或已知明文 crib 反推。
5. **已知明文 crib**：`PK\x03\x04`、`././@PaxHeader`、`*ivicoo*`、`[net]`、`producer_name='pytorch'`——位置对齐后逐字节反推 key。
6. **key 判定**：全局统一 key（一个文件破解即全局）还是 per-file/per-section（头部字段常带 key 版本）；解密后同族文件逐字节对齐校验。
7. **解密校验**：类名表与配置表逐字对齐；权重区字节分布自然（无异常高频字节）；文本层可能有二次转义（如 `0x60+(ch^0xA0)` 类成对转义），数值区单独校验。
8. **身份判定优先级**（从强到弱）：变量语义名（`conv1_sub1/conv_sub4/conv5_4_k1/logit124`→ICNet；`res2a_branch1`→ResNet；`model.22.cv2`→YOLOv8）＞ 训练配置明文（anomalib yaml 的 backbone/layers/coreset）＞ 完整连线重建（OpDesc 全量解析）＞ 权重张量形状（通道演进）＞ 算子计数（仅辅助，会被 attr 污染）。

## 工业视觉软件分析清单（逐项找证据）

1. **软件结构**：进程拓扑（主控/相机端/报表/服务）、插件接口签名、规则注入方式、锚点/ROI 共享机制、发版与回滚痕迹（多版本共存、PDB 构建路径）。
2. **技术栈**：Qt/OpenCV/HALCON/推理框架版本（版本资源 + 导入表精确到 DLL）、通信栈（Modbus/CAN/串口/TCP/UDP）、数据库与报表、**光源控制协议与调光闭环**。
3. **传统算法链**：预处理 → 候选 → 几何/灰度描述 → 工艺规则；记录具体 OpenCV/HALCON 调用序列**与参数（从指令操作数核实，不从伪代码猜）**。HALCON 类注意双模式（ShapeModel+NCCModel）与轮廓回投。
4. **AI 模型身份**：解容器 → 解析计算图（算子**连线关系与变量语义名**，不是算子计数）→ 找训练调用栈/框架指纹（如 icnet.py、ultralytics、anomalib）→ 对齐类别表。检测/分割/异常检测/OCR 分开定性。**解密类名表与配置类别表逐字对齐是终审**。
5. **推理栈与 GPU**：几代后端并存？自研 kernel 还是调库？NMS/Decode 用谁的？upload/download/同步点在哪？"用了 GPU"≠"端到端快"。
6. **规则库与误检控制**：类别分组、Handle/处置语义、过滤类家族、几何/灰度/位置过滤、拒绝日志落盘。改判/降级机制要找到执行函数才算证实。
6.5 **聚合/密集类逻辑**：找距离阈值常量（.rdata 回读）、成员数门限、簇上限、上报类别 ID 的 UI 槽（lineEdit_DenseID 类）；参数常按模型/类别索引成数组（[obj+idx*4+off]），回溯偏移即得逻辑。
7. **执行闭环**：PLC/Modbus 寄存器表、踢废/排废链路、光源协议、IoT/MES 上报、配方与产品切换。
8. **现场性能口径审计**：先确认计时字段能不能相加（抽查 `字段−Σ分项` 的中位数，为负即不可加）；区分在线/离线、Priority、测试动作；转储是选择性样本不能当故障率；计数库分清全局/工位/标签口径，不能相加成产能。
9. **工程质量**：崩溃转储定位到函数（module+RVA+指令），PDB 混用审计，依赖缺口清单，弱口令/明文配置，日志完整性。

## 已踩过的坑（写结论前逐条核对）

- 算子计数区分不了 U-Net/ICNet：只有变量语义名（sub1/CFF/PSP）与连线关系、训练调用栈能定网络身份。**被质疑后补做完整连线重建才算定论；被推翻的原结论要在报告里保留"原结论→修正原因→现结论"链**。
- Paddle OpDesc 的 **attr 名与 op 名同池**（batch_norm 有 "momentum" 属性，32 个会被误计成 32 个算子）；变量名正则漏掉 `_(\d+)` 段（batch_norm_0.tmp_0）会全军覆没。
- 长脚本走 bash heredoc 会静默截断（含大字符串的 f-string 必挂）；**写 .py 文件再执行**。
- 批量产出同名文件会静默覆盖（cam1/cam3 同名包各解一次只剩最后一个）；按目录/序号命名后再合并。
- 同扩展名多容器方案：按文件头分流（差分 XOR 与 16 周期 XOR 共存于同一产品）；一把钥匙套全部会漏解。
- 零区直读 key 比 Crib/频率分析都快：先找"plaintext=0 的长块"，raw 即 key。
- 解密文本层可能有厂商二次转义（成对 `0x60+(ch^0xA0)` 类），数值区单独校验；"缺首字符"的字符串（earning_rate 缺 l）= 转义对被当成单字符吞掉。
- IAT 调用扫描必须按 DLL 过滤：Qt5Widgets 构造函数噪声会把 opencv/halcon 调用挤出 top-50，造成"零 CV 调用"误判（有无检测/旋转边缘实际导入 opencv_world454）。
- 反汇编起点必须是函数边界（.pdata），从猜的偏移开始会落在指令中间全乱。
- 算子计数区分不了 U-Net/ICNet：只有变量语义名（sub1/CFF/PSP）与连线关系、训练调用栈能定网络身份。
- NMS/解码 kernel 要读 PTX 查语义差异：不读被抑制者 keep 标志 = 链式过抑制；atomicAdd 截断上限不是 Top-K。
- 日志计时字段可能互相嵌套/累计，不能当独立阶段相加；"Offline Proess" 类行混有调参动作，不能当在线帧耗时。
- 配置里的预留槽位（如 152 段分切、12 相机槽）不是现场规格，要核对总开关与槽位值。
- 预训练权重带 fc 层不代表部署用了分类头；看部署图实际取哪些层。
- 相机 SN、槽位号、物理编号的对应关系要逐条核对，别照抄单一线索。
- 高熵 ≠ 强加密：差分 XOR、本地密钥随包分发都可静态恢复；无签名/MAC 不能说"防篡改"。
- "当前插件列表未列出"≠"功能不存在"；"随包存在"≠"现场启用"；`开关=0` 时库内能力只能标"未证实启用"。
- 模型文件名后缀（besttransd 等）不能推断网络结构；注意力结构要用层名证据（attn/qkv/MatMul）。

## 报告 Review 三遍法（强制：每份对外报告/导出 PDF 前逐条过）

**Review 1｜拆解深度（自上而下逐算法问五层）**

每个算法结论必须走完五层，任何一层只写了名字没写内容 = 未到底：

```
框架/库（PaddleSeg） → 模型/网络结构（ICNet，非 U-Net） → 函数/调用链（Segment_A1→…→Detect_Defects_A1）
→ 参数（bilateral d=10、σ=20.0、Dense_Num=4） → 常量（聚类半径 30px，.rdata 回读）
```

判定标准：每条算法结论能回答"**输入是什么 / 输出是什么 / 关键阈值是多少 / 阈值从哪来**"。典型失败案例：写了"PaddleSeg"没写 ICNet 就交稿（被外部质疑才发现）；写了函数名没给参数；给了参数没给常量来源。**反面教训：算子计数指纹会给出错误架构（U-Net 误判），必须做连线级重建**。

**Review 2｜首次读者 70% 测试**

以第一次看到这份报告的人的视角通读（或真的换一个会话/找人通读），判定：**首次阅读内能否拿到 70% 的重点**。逐条检查：
- 核心结论是否出现在报告前 1/3 和每节首段（不是藏在证据索引里）；
- 关键数字（延迟、阈值、参数值）是否就地带证据等级标注；
- 首次出现的术语/缩写/内部代号（OuNuo、CFF、Handle）是否就地一句话解释；
- 每节"结论—证据—分析"是否同段可得，不需要翻页拼图；
- 有没有一张总览图/表让读者 30 秒建立全局（阶段总览 SVG、对照表）。
不达标的处理：加每节首句结论、把最硬的数字提到段首、补总览图；**改完再做一遍 70% 测试**。

**Review 3｜事实核对与修正标注**

逐条抽查：文件路径、函数地址、常量值、页数/行数/条数引用是否与**当前产物**一致（改过版本后引用必须同步）；早期结论被推翻的，正文保留"原结论→修正原因→现结论"链，**不静默改**（ICNet 误判案例的标准写法）；证据等级标签（A/B/C/未定）逐条复核，删掉过度自信的标注；解密产物的文件名/页数与清单核对（同名覆盖、旧版残留）。

**三轮全过才允许对外交付（交付物 = HTML）**；三轮发现的问题记入“结论冲突对照”或修正声明，不并入正文悄悄改。

## 报告结构与产出

报告主线：**总体判断 → 软件结构与交付形态 → 传统算法 → 模型资产 → 推理栈与 GPU → 规则与后处理 → 性能与现场数据（含口径修正）→ 执行闭环 → 工程质量 → 竞争力分级 → 可借鉴清单（P0/P1/P2 + 不要照抄的部分）→ 结论冲突对照 → 待验证清单 → 证据索引**。

- 可借鉴清单区分"借鉴什么"与"不要照抄什么"（如链式过抑制语义、弱加密、崩溃模式）。
- 待验证清单列"拿到后会真正改变判断的证据"，不写泛泛的"建议进一步测试"。
- 证据放 `evidence/` 或 `output_<源>/evidence/`；汇总放 `output_conclude/`；报告命名 `YYMMDD+描述`。
- **导出对外交付前跑 Review 三遍法**；跨章节引用时在旧报告的“证据索引”节加指向新报告的链接行。

| 产物 | 信源标注 | 定位 |
|---|---|---|
| `.html`（**最终交付物**） | 剥离信源标记与叙述性提及，保留“早期结论 vs 复核修正”逻辑角色 | 阅读；章节徽标突出技术栈/模型/算法 |
| `.md`（过程底稿，不交付） | 保留（【来源】标签 + 冲突对照） | 撰写与追溯的中间产物，留在工作目录即可 |
| `.pdf`（按需） | 同 HTML | 仅用户点名要 PDF 时导出（打印副本流程见下） |

HTML 转换写一次性脚本（python-markdown + tables/toc 扩展）。注意：内嵌 CSS 色值必须 6 位 hex（5 位会被忽略导致白字贴浅底）；`Engine<float>` 这类裸尖括号在 MD 里改行内代码，否则 HTML 丢字；内嵌大 JS/长文本不进 heredoc，落盘 .py 再执行。**PDF 仅按需导出**：先复制一份打印副本注入 `@media print`（隐藏侧栏、pre 换行防裁剪、行防断），Edge `--headless --print-to-pdf --no-pdf-header-footer`，导出后 pypdf 抽查页数与文本。

## 语言风格

工程口语，像内部技术文档。不用"劣化/确保/可达性"，用"变差/去掉/能发出去"。每个关键结论带证据等级标注；冲突处写清"谁基于什么证据修正了什么"。

## 省 token 举措（已实测，直接套用）

1. **读 HTML 报告先剥壳**：python html.parser 去掉 script/style 转纯文本再读，44KB HTML → 20KB 文本。
2. **字符串导出一次做完**：所有目标 DLL 双编码字符串批量落盘 evidence/，之后只 grep，不重复解析。
3. **配置/数据库解析写一次性脚本**：INI 节清单、SQLite 表结构+计数、minidump 模块表，一条命令出结果，不逐文件人工看。
4. **反汇编分层看**：先调用序列 txt（函数 A→B→C），只对关键函数看指令；大函数先看函数大小与调用次数变化。
5. **模型容器先探测后解包**：magic/长度前缀/熵值判断格式，写可复用 unpack 脚本；解包产物存 evidence 供交叉验证（两个独立解包结果逐字节比对是强证据）。
6. **报告一次成型 Write**，不多次 Edit 拼接；汇总报告先建冲突对照表再填正文。
7. **长脚本落盘 .py 再执行**：内嵌大文本/常量的 heredoc 会被 shell 截断，静默半执行最难排查。
8. **IAT 算法调用过滤前置**：按 DLL 名白名单（opencv/halcon/自有 DLL）过滤后再统计，UI 噪声不进结果集。
9. **模型解密批量产出先查重名**：basename 冲突静默覆盖；先按源路径建子目录再合并。
